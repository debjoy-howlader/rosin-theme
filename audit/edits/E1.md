# E1 edit log

Edit phase 1, applied to `tools/token_rules.py` and `tools/gen.py`, with `themes/*.json` regenerated. Input: A1 change proposals (154). E1 took the 51 proposals with a clear selector-level fix and no open design question; the other 103 carry forward to E2 (see A2).

## What changed

- **Base rule edits** (`BASE_REMOVALS`, `BASE_DROP`): over-broad selectors removed from existing rules so the role-correct rule wins. Examples: `storage.type.struct/union/enum/class/namespace/template` taken out of the composite rule; `markup.inline.raw` out of markup; `string.other.link` out of links; the C++-only `volatile` rule dropped.
- **Type-declaring keywords** now use the keyword colour (P1), so `struct`, `enum`, `class`, `union`, `typedef` read as keywords in every language.
- **New TextMate rules** (`e1_rules`): Rust, C/C++, doc-comment delimiters, Python decorators, Kconfig, devicetree, ARM assembly, Make, CMake, shell `&&`/`||`, git commit subject, Markdown inline code and link text.
- **New semantic selectors** (`extra_semantic`): `const`, `static`, decorators (`*.decorator`, builtin decorators), `magicFunction`, `function.builtin`, `variable.classMember`, `class.builtin`.
- **E1b follow-up**: two collateral moves found by the what-if were corrected before A2 (`template`/`typename` fell to prim, so a keyword rule was added; `variable.named.arm` coloured every ARM identifier, so it was removed). The E1b what-if moved exactly the 7 intended tokens.

Full source diff: [`E1-source.diff`](E1-source.diff).
