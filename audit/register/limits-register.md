Generated by `tools/readme_languages.py` from `limits-register.json`, which `audit/harness/register.py` builds from the final audit (`audit/reports/A5-*.json`). One row per checked token and mode where the colour is not the one the meaning table gives. The Mode column is the language server installed ("no server" is the grammar alone).

## Reason codes

| Code | Meaning |
|---|---|
| NS | no distinguishing scope: the token is unscoped or carries only container scopes shared by other roles |
| ID | the grammar encodes the identifier text in the scope (variable.other.unknown.<name>); a rule would match one spelling, not the role |
| SS | the grammar gives this token the same innermost scope as a token of another role; only containers differ, and they do not separate the roles |
| GE | the grammar does not tokenize this construct at all |
| SV | the language server labels this token the same as a token of another role, or emits nothing for it |
| DV | the servers disagree; by P3 the server verdict stands, so the colour depends on the server in use |
| ENV | environment limit E-01 (rust-analyzer cannot resolve std macros on this toolchain) |
| NEEDS-SERVER | only a language server can tell this role; the grammar alone gives the declared fallback colour |
| DESIGN | deliberate: a multi-part token is coloured part by part as the meaning table says (not a limit) |
| SPLIT | the grammar splits the token into parts with different scopes; the parts are coloured as designed or the split itself is the limit |

DESIGN rows are not exceptions: the token is coloured part by part on purpose. They are listed for completeness.
