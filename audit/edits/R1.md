# R1: refactor (zero-diff)

**Change.** `prune_shadowed()` in `tools/token_rules.py`, applied in `tools/gen.py` to the final rule list. A scope selector that a later rule redefines with both foreground and fontStyle is removed from the earlier rule (TextMate keeps only the later one). Rules left without a scope are dropped.

**Why.** 16 scope selectors were defined twice in every theme. The earlier definitions never rendered, but six of them carried a different colour from the winning rule (CMake property, Devicetree node/property/label, Kconfig storage type), which made the source misleading to anyone reading it.

**Removed (Sea Salt; identical selectors in all six themes).**

| Earlier rule | Selector it lost |
|---|---|
| Doc comments | `comment.block.documentation` |
| Functions (iris) | `entity.name.label` |
| Parameters | `variable.language.special.self` |
| Parameters | `variable.language.special.cls` |
| this / self-like language variables, registers | `variable.other.register` |
| this / self-like language variables, registers | `support.constant.register` |
| this / self-like language variables, registers | `storage.type.register` |
| Assembly (extension-dependent) | `support.function.mnemonic` |
| Assembly (extension-dependent) | `keyword.other.mnemonic` |
| Assembly (extension-dependent) | `keyword.mnemonic` |
| Sections (INI/TOML/Markdown) | `markup.heading` |
| CMake properties | `support.type.property.cmake` |
| Devicetree nodes | `entity.name.type.dts` |
| Devicetree properties | `variable.name.dts` |
| Devicetree / Kconfig directives | `storage.type.kconfig` |
| Devicetree labels & phandles | `entity.name.function.dts` |

**Result.** tokenColors 176 → 175 rules per theme; duplicate selectors 16 → 0; `colors` and `semanticTokenColors` unchanged. `audit/harness/diff.js` on the full corpus, old vs new themes, mode T and every server dump: 131,208 token-runs compared, 0 moved.

**Next audit must re-check.** Nothing new. A new rule whose scope already exists now overrides the earlier one and the earlier one is pruned at build time, so the diff report is where to see the effect.
