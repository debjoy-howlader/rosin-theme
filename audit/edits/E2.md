## Rules added (`e2_rules`, `extra_semantic`, `semantic_overrides`)

- **C / C++**: `extern` (linkage) → qualifier; `decltype`, `noexcept`, `requires` → keyword; `__VA_ARGS__` → parameter; words inside inline-asm strings stay string; `[[nodiscard]]` and other standard attributes → directive; `u8` / `L` / `R` string prefixes → string; user-defined literal suffixes → unit; class member declarations → member.
- **clangd**: `auto` / `decltype` deduced types (`type.deduced`) → keyword; constructors and destructors → function; concepts → composite; file-scope (static) variables → static variable.
- **cpptools**: user-defined literals (`numberLiteral`, `stringLiteral`, `customLiteral`) → unit.
- **Rust**: `macro_rules!`, `static`, `super` → keyword; `Some` / `None` / `Ok` / `Err` → number (enum variants); float exponent → unit; `::` → namespace (same as C++). rust-analyzer: std structs and enums (`String`, `Result`, `Box`) → primitive (P2).
- **Python**: `global` / `nonlocal` → keyword; line-continuation `\` → escape; imaginary `j` → unit; raw-string body → string while regex escapes inside keep the escape colour; dunder method definitions → method; `metaclass=` → parameter. Pylance: library functions → library function, library decorators stay directive.
- **Shell**: `$'...'` and `<( )` delimiters → string; `=~` → operator; `alias` → keyword; alias names → function.
- **Build and config files**: linker-script section and region names → user type, symbols in expressions → config variable; Make prerequisites → function; CMake `$<` `>` → hazard; YAML `---` `...` → punctuation, `<<` → member, list `-` → keyword; TOML dotted keys (Even Better TOML) → member.
- **Diff / git / devicetree / ARM**: `---` `+++` `***` file headers and "Only in" lines → comment; `@@` → directive; `new file:` / `deleted:` in commit comments → keyword; `&label` references → function; ARM `[ ]` and `{ }` → punctuation.

## Corpus corrections

- `cpp.number.suffix.float`: the marker pointed at the variable name `fl`, not the `f` suffix (`~f#2` → `~f#3`).
- `rs.type.string`, `rs.kw.result`: std types are primitive under P2; without rust-analyzer the grammar gives every type the same scope, so the user-type colour is the allowed fallback (`prim/T:composite`).
- `rs.assocfn.call` (`String::new`): a std function is a library function (`libfn/T:function`).
- `py.import.name`: an imported library function takes the library-function colour (`libfn/T:directive`).
- `py.raw.string`: the marked token is the regex escape `\d`, which keeps the escape colour.

## Problems caught during the edit

- **Linker input sections**: a rule for memory attributes (`rx`) also coloured input-section patterns (`.text*`, `.isr_vector`), which share the same scope. Reverted; recorded as a limit.
- **Python regex escapes** lost their colour once the raw-string body got the string rule. Fixed with a deeper rule for escapes inside regex strings.
- **Pylance library decorators** (`@dataclass`) fell to library function because `function.library` outranked `*.decorator`. Fixed with explicit `function.decorator.library` / `class.decorator.library`.
- **`gen.py` merge bug**: extra semantic rules were merged with `setdefault`, so they could add keys but never replace a base entry. The fileScope change was silently ignored. Added a `semantic_overrides()` hook that replaces keys explicitly.

## What-if

`e2-diff.json`: 111,828 token renderings across 6 flavours, mode T and all server dumps; 1,162 moved. Every moved group was reviewed by innermost scope and text before the re-audit.

## Known trade-off

cpptools gives a user-defined literal declaration (`operator""_ms`) the same token type as its uses (`250_ms`), with no modifier. Both now take the unit colour. Declarations were correct before and are now wrong; uses were wrong before and are now right. Uses are far more common, so the trade was kept and recorded as a limit.
